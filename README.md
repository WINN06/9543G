## Why Are We Here?

# Starting with AI-Assisted Development
In 2024, I began using Unity to create independent games, and this was how I first encountered programming. By then, generative AI had already become a powerful coding assistant. For an independent developer with no previous programming experience, this seemed like perfect timing: I did not have to wait until I became a competent programmer before testing my ideas.
AI helped me write almost all the code in my projects, turning systems I could describe but could not build alone into playable features. What attracted me most was the speed. At first, this made me wonder whether learning programming in a formal course was still necessary.

I began with online resources, learning the basics of C# and following established YouTube tutorials to complete several small game demos. Once I understood the general logic of how Unity worked, I started developing my own projects. At first, the process went smoothly because tutorials existed for most of the functions I needed. I could follow an example, type or copy the code into Visual Studio Code, attach the script to a GameObject, and run it in Unity. If the tutorial did not match my idea exactly, I asked ChatGPT to modify the script, pasted the revision back into my project, and tested it again. I could move from an idea to a playable prototype before fully understanding the technical details. This made programming feel immediately accessible.

# When Working Code Was Not Enough
However, I soon discovered a gap between the basic C# I had learned and the complexity of the scripts I was actually using. I could sometimes make a script run, but I could not explain how it worked. I often needed ChatGPT to explain the code line by line. When a bug appeared, I could not identify its cause, so I could only describe the visible problem and repeatedly ask the AI to revise the code. Sometimes each revision introduced a new error or created a conflict with another system. I searched forums for similar experiences, and some bugs still took several days to fix.

The problem became clearer as my projects grew. Scripts rarely worked in isolation: one change could affect several connected systems. Without understanding those relationships, debugging became a process of guessing. I was often testing patches rather than understanding why the problem had appeared.

Eventually, my projects began to feel like piles of code taken from tutorials and generated by AI. They worked, but they felt fragile. I was afraid to change one script in case it broke another, and I sometimes abandoned game ideas because I did not know how to implement them safely.

# From Code Generation to System Design
Looking back, my experience was not unique to AI-assisted development. While learning Unity, game designer Mark Brown described how following tutorials allowed him to produce a working game, yet when he later opened a blank project, he realised he could barely build anything independently. He eventually shifted toward recreating simple games, experimenting, and breaking problems into smaller steps (Brown, 2021). His experience helped me see that being able to produce a result is different from understanding how a system works. AI makes this gap even easier to overlook because it can generate a solution before I fully understand the problem. 

For me, this distinction changed how I think about programming. Receiving working code is not the same as designing a good system. Good code is not necessarily the shortest code. It should be clear, modular, and maintainable: each script should have an understandable responsibility, connections between systems should be traceable, and features should be adjustable without making the whole project collapse. To reach that point, I need to understand variables, functions, conditions, events, states, and the relationships between different systems.

With this knowledge, I can give AI more precise instructions, judge whether its answers make sense, locate bugs, and recognise when I should reorganise a system instead of adding another temporary patch.

# Why I Am Learning Programming Now
Therefore, I am sitting in this programming class not because I expect to compete with AI by writing every line faster or from memory. The role of programming in my practice is changing: reading, questioning, and organising code may become more important than memorising syntax. However, that does not make programming knowledge unnecessary. For an independent game designer, code is a creative material alongside images, sound, and narrative. Mechanics, rules, interactions, and pacing all depend on logic. If I do not understand that logic, I do not fully control my design; I can only accept whatever the tool happens to produce. I want AI to extend my ideas, not determine their boundaries. Learning programming gives me the agency to build more stable systems, communicate my intentions clearly, and pursue ideas that I might otherwise abandon. That is why I am here.
